# 下载季集校验

提供两种处理模式：默认校验种子文件与搜索匹配的季集是否一致；也可以信任搜索结果，
自动生成任务专属 `custom_words`，让原生整理沿用搜索匹配的季集。

例如站点标题匹配为 `S01E50`，种子内文件名却是：

```text
The.Apothecary.Diaries.S03E02.The.Fire-Rat.Cloak.1080p.NF.WEB-DL.AAC2.0.H.264-VARYG.mkv
```

默认模式会在视频开始下载之前拦截这条资源，继续尝试其他候选。
沿用模式则为这个下载任务生成 `S01E50` 的识别覆盖，整理后的季集、历史和刮削都使用原生流程。
它信任搜索匹配的集号，不能据此证明视频实际内容确实是第 50 集。

## 安装

支持 **MoviePilot >=2.15.6,<3**；本仓库只提供 V2 插件。

1. 在 MoviePilot 插件市场设置中添加本仓库地址：
   `https://github.com/z-henry/MoviePilot-Plugins`。
2. 刷新插件市场，安装“下载季集校验”。
3. 开启“启用下载季集校验”。
4. 选择处理模式。默认是“校验一致性”，建议保留“仅检查订阅下载”。

插件默认关闭，安装后需要启用。旧版配置升级后仍使用校验模式，保留原来的无法校验开关。

## 两种模式

| 场景 | 校验一致性（默认） | 沿用搜索季集（custom_words） |
| --- | --- | --- |
| 搜索 `S01E50`，文件 `S03E02` | 明确冲突，跳过 | 为该任务生成 `S01E50` 识别覆盖 |
| 单个视频没有可识别集号 | 按“无法校验时跳过资源”处理 | 能生成并预检覆盖规则时允许 |
| 元数据获取失败、磁力超时 | 按开关跳过或放行 | 固定跳过 |
| 多集资源 | 按下文的集合校验规则处理 | 当前不猜测多文件与目标集的映射，固定跳过 |
| “无法校验时跳过资源”开关 | 显示且生效；明确冲突不受它影响 | 隐藏，后端不使用这个开关 |

### 沿用搜索季集

目前只支持 **一个明确的目标季集、一个正片视频**。常规样片被排除；与正片同目录、
同名或带语言尾缀的字幕一并生成覆盖。同名文件、多个正片、多个目标集、哈希冲突、
规则生成失败或识别预检失败都会跳过，让订阅继续尝试其他资源。

1.2.1 起单集使用 `s=1;e=26` 这样的单值覆盖，最终季集格式为 `S01E26`。
如果识别后仍残留原文件／目录的季集范围，也会跳过，避免沿用错误的结束集号。
1.2.0 已保存的任务快照和已整理文件不会在升级时自动修改，需要单独修复。

1. 下载前冻结 MP 已完成搜索识别／识别词转换后的媒体身份和目标季集。
2. 使用种子元数据取得哈希和确切文件名，保留本次订阅识别词（没有则冻结全局识别词），
   在原有转换之后追加只匹配该文件名的季集覆盖规则，并通过当前 `MetaInfoPath` 预检。
3. 在 MP 新增下载历史的同一数据库事务内，把规则存入该记录的 `custom_words`。
   同时在 `note.episodeguard_snapshot` 保存媒体身份、目标季集、文件名和原始识别词备份。
   只绑定哈希、下载来源、媒体身份、季集和原始识别词全部匹配的记录，不能覆盖同哈希的其他目标。
4. 请使用 **下载器监控整理**：原生整理用任务哈希读取下载历史中的识别词，随后正常识别、
   重命名、写历史和刮削。插件在文件操作之前再用整理队列的任务哈希检查媒体和季集，
   不凭相似标题、同名文件或目录猜测任务归属，也不通过修改最终文件名伪装正确识别。
5. 如果极少数整理任务在历史提交前已拿到旧元数据，会先拦截文件操作；只对插件自身的
   这类失败尝试一次重新入队，等待快照最多检查三次，不清理已成功的入库文件。
   无法安全重试时停止并记录原因，可在历史中手动重新整理。

待绑定计划保留 24 小时、最多 128 条，重载后可继续绑定；已经写入下载历史的规则不依赖该计划的期限。
不修改全局识别词或订阅识别词，也不改变其他哈希的下载历史。任务成功绑定后，后续修改订阅词表
不会改变它的快照。关闭插件／切换模式影响后续资源处理，**已有下载历史的识别词仍由原生整理使用**。
此版本不自动处理升级前的下载任务，也不提供回滚历史识别词的按钮。

下载器监控能直接传递任务哈希；目录监控需要原生路径历史匹配，在文件集号冲突、文件记录未登记
或多个任务共享目录时不能保证找到正确历史，因此不要用目录监控作为沿用模式的关联依据。

1.1.0 增加 `libtorrent==2.0.11` 依赖，由 MP 在插件安装／更新时安装。
支持 Python 3.11／3.12 常见 Linux x86_64 和 ARM64 环境；没有可用依赖时，
磁力资源会归为“无法校验”，不影响普通种子地址的校验。沿用模式对普通种子也需要此依赖计算任务哈希；
依赖不可用时固定跳过。SQLAlchemy 使用 MoviePilot 已有依赖，无需额外安装。

## 磁力链校验

只检查 MP 提供的资源，不抓取站点详情页，不在插件中维护网站适配规则：

- `.torrent` 地址或需要解析的下载地址：仍调用 MP 的获取逻辑，沿用其认证、代理和缓存。
- 磁力链（也包括 MP 解析下载地址后返回的磁力链）：通过 Tracker／DHT 和 BT 元数据协议
  获取内部文件列表，核对元数据哈希，再沿用同一套季集识别规则。
- 只获取种子元数据，不请求视频分块，不向现有下载器创建临时任务。
- 每条未缓存的磁力资源独立最多等待 15 秒，前面的资源超时不缩短后面资源的校验时间。
  同一哈希仍复用缓存。没有整次搜索的共享等待预算；候选较多时，搜索耗时会相应增加。
- 最多并发 2 个独立校验进程，每个最多连接 12 个节点；超时结束进程并清理临时目录。
- 元数据按哈希缓存在内存中，成功缓存 24 小时，失败缓存 5 分钟；
  最多 128 条、16 MiB，单个元数据最多 2 MiB。插件重载后缓存清空。
  缓存不保存“允许／拦截”结论，因此修改订阅识别词后会重新判断。
- 如果该站点启用代理，磁力元数据连接目前支持 SOCKS5；仅有 HTTP 代理时会归为
  “无法校验”，不会绕过代理改用直连。普通种子地址仍使用 MP 支持的代理。

冷门磁力没有可用节点时可能拿不到元数据。校验模式下，超时、依赖不可用等情况遵守
“无法校验时跳过资源”开关：开启则跳过；关闭则放行。明确季集冲突始终拦截。
沿用模式不能在没有元数据的情况下生成规则，这些情况固定跳过。

## 校验模式的规则

| 场景 | 处理方式 |
| --- | --- |
| 订阅下载的单集资源 | 内部正片季集必须与候选目标一致 |
| 标注集数范围的合集 | 检查所有内部正片的季集集合，缺集或额外集均拦截 |
| 主程序选择部分集下载 | 必须覆盖选中集，允许同季其他集；其他季的视频会被拦截 |
| 未标注集数的整季资源 | 使用订阅开始集和总集数检查覆盖，允许同季较早的集 |
| 配置了订阅识别词 | 使用与整理相同的识别词解析；已正确配置的季集偏移不会被误拦截 |
| 没有订阅识别词 | 保留 MoviePilot 全局识别词回退 |
| 文件夹带季号 | 使用 `MetaInfoPath`，保留文件继承父目录季号的行为 |
| 样片与字幕 | 忽略常规 sample/trailer 视频和非视频文件 |
| 手动下载、电影、音乐 | 默认不检查；关闭“仅检查订阅下载”后可检查手动下载的电视剧 |

插件核对的是识别后的季集，不要求网页标题与文件名文本完全相同。
如果文件 `S03E02` 已通过订阅识别词正确映射为 `S01E50`，会允许下载。

## 校验模式下无法校验的资源

“无法校验时跳过资源”默认开启，包括：

- 磁力元数据获取失败、超时、依赖不可用或代理不支持。
- `.torrent` 读取失败、内容无法解析。
- 没有可识别的正片视频，或正片缺少可确定的季集。
- 整季候选没有可靠的开始集／总集数范围。
- 多季合集：本版不猜测单季订阅与多季包之间的映射。
- 无法读取本次订阅及其识别词。

关闭该选项会放行这些无法判断的资源，并记录“放行（未校验）”。**明确季集冲突仍然会拦截。**

## 查看记录

插件详情页保存最近 50 条冲突、无法校验以及覆盖规则待绑定／已绑定记录，包含站点、标题和原因。
主程序日志也会记录检查结果。不主动发送通知，避免每次匹配产生消息。

拦截后不会把该集记为已下载。当前批次还有其他候选时继续尝试；全部候选被拒绝时保留缺集，
等待后续订阅刷新或搜索。下次搜索可能再次检查同一资源。

## 实现与限制

- 使用官方 `ChainEventType.ResourceDownload` 事件，通过 `cancel=True` 否决本次资源。
- 不修改或包装主程序方法，不直接修改订阅缺集记录，不自行添加下载任务。
- 沿用模式使用 SQLAlchemy 公开的 `before_insert` 监听器绑定新下载历史，重载／停止时移除监听器。
  这不是 MP 官方的识别词输出事件，依赖 V2 下载历史模型及原生整理读取 `custom_words` 的行为；
  已针对本机 V2 2.15.6 验证，主程序升级后应重新验证兼容性。
- 使用宿主 `DownloadChain.download_torrent` 获取种子元数据，复用 Cookie、代理、
  间接下载地址处理和种子缓存。普通 URL 通常复用缓存，短时凭证或换票地址可能增加站点请求。
- 事件不携带主程序已经读取的种子字节，因此无法保证所有地址只请求一次。
- 只核对季集，不验证视频实际内容，也不校验相同季集的文件是否真的来自目标剧。
- 不处理已经下载或已经整理的文件。
- 事件取消后的失败／冷却和下次重搜时机由 MoviePilot 控制。
- 磁力校验依赖 `libtorrent==2.0.11`；校验模式的 HTTP 种子路径不加载此依赖。

## 开发验证

在仓库根目录执行：

```bash
python3 -m venv /tmp/episodeguard-tests
/tmp/episodeguard-tests/bin/pip install -r plugins.v2/episodeguard/requirements.txt
/tmp/episodeguard-tests/bin/pip install SQLAlchemy
/tmp/episodeguard-tests/bin/python -m unittest discover -s tests -p 'test_episodeguard*.py' -v
```

测试使用模拟应用边界，不接触实际站点或下载器。若 `/tmp/mpv2-download.py` 存在对应的 V2
主程序源码，还会直接执行其中的候选循环，验证第一候选被拦截后继续处理第二候选。
协议测试使用本机模拟 BT 节点，关闭 DHT，不访问外部站点或下载器；验证取得哈希匹配的
元数据、未发送视频分块请求、未创建视频文件。未安装 libtorrent 时跳过原生协议测试。

在有 V2 容器的开发机器上，可进一步运行：

```bash
python3 scripts/episodeguard_native_probe.py --container moviepilot-v2 --sudo
```

验证脚本只在内存中调用容器实际的种子解析器、识别词处理器和 Rust 路径识别器，
通过合成种子检查季集冲突、正确单集、偏移规则、父目录季号、字幕／样片以及沿用模式。
沿用模式使用内存 SQLite 验证事务绑定，检查 Rust／Python 词表转换结果一致，
不连接实际数据库。应用边界被模拟，不访问站点，不写服务文件或设置，也不产生实际下载任务。
